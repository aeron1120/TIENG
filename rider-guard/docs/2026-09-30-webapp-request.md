Rider Guard 웹앱 수정 요청
Codex 전달용 | 2026-09-30
대상: https://rider-guard.expo.app/home

이 문서를 기준으로 현재 저장소를 확인하고 웹앱을 수정해 주세요. Google Cloud Console에서 사용자가 직접 수행할 등록 절차는 별도로 안내되어 있습니다. 여기서는 앱 코드·인증 연동·사고 후보 판정·화면·기록을 구현합니다. 기존 보호 / 기록 / 설정 구조와 디자인을 유지하세요.

1. 작업 시작과 범위

- AGENTS.md, README, package.json, 잠금 파일, Expo 설정, 인증·API·DB·배포 코드를 먼저 확인합니다.
- 현재 인증이 Supabase, Firebase, 자체 서버 중 무엇인지 확인하고 기존 구조를 재사용합니다. 확인 없이 새 인증 서비스나 DB를 도입하지 않습니다.
- 웹앱을 우선 완료합니다. Android·iOS 네이티브 로그인, 실제 잠금화면 알림·음성 하드웨어 추가 개발은 기존 지원 범위를 확인하고 별도 필요 작업으로 구분합니다.
- 센서 판정이 ESP32·앱·서버 중 어디에서 실행되는지 확인합니다. 웹앱이 원시 IMU를 직접 수신한다고 가정하지 않습니다. 기존 판정 위치와 데이터 전달 구조에 맞춰 연결합니다.
- 수정 가능한 코드를 먼저 완성하고, 필요한 Console 등록값과 환경변수를 정확히 반환합니다. 비밀값이 없다는 이유로 모든 구현을 중단하거나 가짜 로그인으로 대체하지 않습니다.
- 자동화 검증·미리보기에서는 실제 비상연락처나 119로 연락하지 않는 별도 전송 어댑터를 사용합니다. 실제 전송 성공을 시뮬레이션하지 않습니다.

현재 화면에서 확인한 내용

- /home: 마지막 위치 지도, 보호 시작·착용 시간, 헬멧·음성 응답·위치 수집 상태, 비상연락처 카드.
- /records: 사고 기록 목록과 보험·산재 접수 관련 안내.
- /settings: 헬멧 착용·음성 응답, 동의 관리, 긴급 알림 및 잠금화면 미리보기.
- /emergency: 충격 감지 후 본인 무응답 안내, 마지막 위치·기준 시각, 다음 연락처 알림 카운트다운, 전화·대응 확인·연락 불가·119 신고 완료 버튼.
- /lockscreen: 보호 상태·착용 시간·헬멧 연결·배터리·비상연락처 수락 상태 미리보기.
- 검토 당시 홈·기록·일부 설정 데이터가 로딩 상태로 남았습니다. 원인이 인증·API·환경 설정 중 무엇인지 확인하세요. 공개 화면만 보고 백엔드 고장이나 구현 완료를 단정하지 않습니다.

2. Google 로그인 구현

2.1 로그인과 세션

- 로그인 화면에 'Google로 계속하기'를 연결합니다. 기존 인증 SDK를 우선 사용하고, 직접 웹 로그인을 구성한다면 Google Identity Services 등 현재 지원되는 방식을 사용합니다.
- 처리 중 버튼 중복 클릭을 막고, 로그인 취소·팝업 차단·네트워크 오류·설정 불일치를 구분합니다. 취소 시 재시도할 수 있어야 합니다.
- 자체 서버 방식은 ID token의 서명, aud, iss, exp를 검증한 뒤 Rider Guard 세션을 생성합니다. JWT decode 또는 클라이언트가 보낸 이메일만으로 인증하지 않습니다. Google 사용자는 sub로 식별합니다.
- Supabase·Firebase 방식은 제공자의 인증 세션을 사용합니다. 별도 API가 있으면 그 서버에서도 제공자의 토큰을 검증합니다.
- 선택한 OAuth 흐름의 state·PKCE·nonce·CSRF 처리를 SDK·공식 문서에 맞게 적용합니다. Client Secret이 필요한 교환은 서버 또는 인증 제공자에서 처리합니다.
- Client ID는 공개 설정으로 사용할 수 있습니다. Client Secret·서비스 관리자 키 등 비밀값은 EXPO_PUBLIC_* 변수, 브라우저 번들, Git, 클라이언트 로그에 넣지 않습니다.
- 세션 상태를 loading / authenticated / unauthenticated / error로 구분합니다. 새로고침·새 탭·만료·로그아웃 시 일관된 상태를 유지합니다.
- 사용자 생성은 반복 로그인에도 중복되지 않게 합니다. 동일 이메일이라는 이유만으로 기존 계정을 임의 병합하지 말고 인증 제공자의 안전한 계정 연결 절차를 따릅니다.

2.2 라우팅과 데이터

- 인증 완료 전에 보호·기록·설정의 사용자 데이터를 잘못 요청하지 않습니다. 복원 완료 후 인증 상태에 맞는 화면으로 이동합니다.
- 로그인 성공 시 세션 저장·교환을 완료한 뒤 /home 또는 허용된 원래 목적 화면으로 이동합니다. 외부 임의 주소로 이동하는 return URL은 허용하지 않습니다.
- 사용자 ID에 연결된 비상연락처·사건·동의를 불러옵니다. API/DB에서 소유권을 검사하여 타인 데이터 조회·변경을 차단합니다.
- 설정의 로그인 방식·내 정보·로그아웃에 실제 인증 상태를 연결합니다. 로그아웃 후 이전 사용자의 위치·기록 캐시를 화면에 남기지 않습니다.
- 라이더 전용 로그인 화면과 비상연락처 수신자용 긴급 페이지를 구분합니다. 수신자는 기존의 사건·수신자 범위 권한으로 필요한 정보만 접근하도록 합니다.
- 요청 실패·빈 데이터·미인증을 무한 로딩과 구분합니다. 오류 원인에 맞는 안내·재시도 또는 빈 상태를 제공합니다.

2.3 사용자가 Console에 입력할 값 반환

소스를 확인한 후 다음을 확정값으로 정리해 주세요. 사용자에게 Secret 값을 채팅으로 보내라고 요청하지 않습니다.

- 현재 인증 제공자와 선택한 로그인 흐름.
- 운영 JavaScript origin: https://rider-guard.expo.app
- 로컬 JavaScript origin: 실제 개발 포트 기준.
- Google Cloud에 등록할 정확한 OAuth redirect URI. JS popup callback 방식이라면 필요 여부를 명시.
- 인증 제공자에서 따로 등록할 앱 복귀 URL과 승인 도메인.
- Client ID 및 필요한 서버 비밀값의 환경변수 이름·입력 위치·배포 반영 방법.
- Supabase이면 제공자 callback과 앱 redirectTo를 구분합니다. Firebase이면 authDomain/__/auth/handler와 앱 도메인을 구분합니다. /home을 Google callback으로 임의 지정하지 않습니다.

3. 센서 사고 후보 규칙

아래 값은 보고서의 기존 규칙을 재현하기 위한 초기값입니다. 최적 임계값 또는 상해 심각도 기준으로 표현하지 않습니다.

- 가속도 기준: 3축 합성 크기 6g 이상.
- 각속도 기준: 3축 합성 크기 300°/s 이상.
- 추정 ΔV 기준: 3m/s 이상.
- 헬멧 추정 뱅크각: 절댓값 45° 이상.
- 여러 조건을 결합하는 창: 최근 0.5초.
- ΔV 계산 창: 150ms.
- 최초 판정 시작: 기록 시작 150ms 후. 센서 보정 완료 시간과 별개.

논리:
최근 0.5초 안에서 가속도 >= 6g
AND
(각속도 >= 300°/s OR 유효한 추정 ΔV >= 3m/s OR 사용 가능한 추정 뱅크각 절댓값 >= 45°)

구현 조건

- 모든 지표는 같은 표본에서 통과할 필요가 없지만 같은 0.5초 창 안에 있어야 합니다. 전체 실행의 서로 멀리 떨어진 피크를 결합하지 않습니다.
- 가속도는 중력의 지지 효과를 포함하는 센서 크기입니다. ΔV는 자세를 이용해 중력을 제거한 150ms 속도벡터 변화량의 크기이며, GPS 속력 감소량이 아닙니다.
- 판정과 적분은 센서 시각을 기준으로 합니다. 수신 시각과 순번을 별도로 기록하며, 묶음 수신으로 수신 시각이 같아진 표본을 0ms 간격으로 적분하지 않습니다.
- 무효 ΔV는 null 및 사유로 저장하고 0으로 대체하지 않습니다. 누락을 가로지르는 적분창은 보고서의 재현 기준에서 무효로 처리합니다. 보간 등 새 정책은 별도 버전으로 검증합니다.
- 가속도·각속도로 후보가 발생하면 ΔV 무효 때문에 이를 취소하지 않습니다. 입력 부족으로 조건 성립 여부를 판단할 수 없으면 '정상' 대신 '판정 정보 부족'으로 처리합니다.
- 최초 후보가 생기면 사건 단위로 유지합니다. 순간 수치 하락으로 해제하지 않습니다. 사건 종료·재감시·중복 이벤트 억제는 별도 상태 전이로 처리하고, 같은 사건에서 알림을 반복 생성하지 않습니다.
- GPS 속도 > 0, 기울기 통과, ΔV 통과를 새로운 필수 조건으로 추가하지 않습니다. 정지 중 피충돌과 전도 없는 충돌을 포함해야 합니다.
- 축별 포화와 합성 크기를 구분합니다. 보고서의 출력 레일 접근 기준은 어느 축이든 |raw| >= 32760입니다. 이 값이 모든 내부 과입력을 검출하는 것은 아닙니다.
- ±16g·±2000°/s는 축별 범위이므로 합성값은 이를 넘을 수 있습니다. 포화값을 실제 최대 충격으로 확정하거나 그 값으로 상해 등급을 만들지 않습니다.
- 자세 품질 때문에 각도·ΔV 분기를 제한하는 변경은 원래 규칙과 비교 검증합니다. 임의의 정확도·신뢰도 백분율을 표시하지 않습니다.
- 기록률은 1kHz를 비교 출발점으로 실제 장비 설정을 확인합니다. 웹 화면 갱신률을 낮춰도 원시 기록과 후보 판정은 유지하고, 그래프 축약 시 피크가 사라지지 않게 합니다.

4. 화면별 수정

4.1 보호 화면

- 기존 지도·카드 배치를 유지합니다. 헬멧 착용, 장치 연결, 최신 센서 수신 여부를 구분합니다.
- 센서 수신이 확인되면 '보호 중', 연결이 끊기면 '센서 연결 확인 필요', 초기 수신 대기이면 '센서 정보 대기 중' 등 실제 상태를 표시합니다.
- 연결 끊김·오래된 데이터의 판단 시간은 기존 통신 주기와 코드를 확인하여 정하고 설정값으로 남깁니다. 보고서에서 검증한 사고 임계값과 혼동하지 않습니다.
- 음성 응답·위치 수집 가능 상태를 표시합니다. GPS 부재만으로 IMU 감지를 끄지 않습니다. 지도에는 위치의 마지막 갱신 시각을 표시합니다.
- 홈에는 상세 센서 수치와 개발자용 임계값을 모두 나열하지 않습니다.

4.2 본인 확인과 긴급 알림

- 사고 후보 감지 후 '사고가 의심돼요. 괜찮으신가요?'로 확인합니다.
- '괜찮아요'·'도움이 필요해요'와 음성 응답을 같은 사건 상태에 연결합니다. 음성 미지원 환경에서는 화면 응답을 제공합니다.
- 음성 인식 실패와 본인 무응답을 구분합니다. 응답 대기 종료와 실제 응답 상태를 근거로 후속 처리를 진행합니다.
- 수신자 안내는 발생 사실에 맞춥니다. 예: '강한 충격이 감지됐고, 본인 응답을 확인하지 못했어요.' 도움 요청에 응답한 경우에는 다른 문구를 사용합니다.
- 본인 응답 대기와 다음 연락처 알림 대기는 센서의 150ms·0.5초와 별개입니다. 기존 값을 확인하여 보존·문서화하고, 임의의 새 대기 시간을 보고서의 검증값처럼 추가하지 않습니다.
- 감지, 확인 대기, 본인 응답, 연락 요청, 실제 전송 결과, 연락처 대응, 종료를 구분합니다. 사건 상태 전이는 재시도·여러 기기의 동시 응답에도 중복되지 않게 처리합니다.
- '119에 신고했어요'는 사용자의 신고 완료 응답으로 기록합니다. 이 버튼만으로 앱이 119에 직접 신고했다고 표시하지 않습니다.
- 감지 알림 취소를 곧바로 '실제 사고 아님'의 정답 라벨로 저장하지 않습니다.

4.3 기록 목록과 상세

- 목록: 사건 발생 시각, 위치, 대응 상태·결과를 간결히 표시합니다.
- 상세: 최초 후보 시각, 판정에 사용된 지표·값·각 통과 시각, 임계값·규칙 버전을 표시합니다.
- 측정 품질: 일부 누락, 축별 포화, ΔV 계산 불가를 사건 상태와 함께 표시합니다. 예: '사고 후보 감지 / ΔV 계산 불가'.
- 파형 상세: 지표별 단위·임계선·판정창·후보 시각을 표시합니다. 결측은 선을 끊고 포화 구간을 표시합니다.
- 사건의 감지 근거와 실제 사고 확정 여부를 구분합니다. 센서 피크로 경상·중상·보험상 판단을 생성하지 않습니다.
- 보험·산재용 기록 제공 문구는 실제 저장·내보내기 기능과 일치시킵니다. 파일 제공 여부와 외부 기관에서 인정하는지는 별개입니다.

4.4 설정과 미리보기

- 일반 사용자 설정에 임계값 조절 슬라이더를 추가하지 않습니다. 개발자 설정·로그에서 기준과 버전을 관리합니다.
- Google 로그인 동의는 위치·센서·의료정보 제공 동의를 대체하지 않습니다. 기존 동의를 실제 수집·전송 경로에 연결합니다.
- Google 로그인 때문에 Gmail·Drive·Google 연락처 접근 범위를 추가하지 않습니다. 비상연락처 등록은 별도 앱 기능입니다.
- 웹에서 지원되지 않는 알림·음성 하드웨어 기능을 실제 작동 중으로 표시하지 않습니다.
- 미리보기에는 시뮬레이션·mock·실제 측정 출처를 표시합니다. 실제 전송과 데모 전송을 분리합니다.

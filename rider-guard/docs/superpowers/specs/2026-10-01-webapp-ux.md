# 웹앱 시연·사용성 개선 명세

사용자 요청: 앞서 제안한 웹앱 개선사항을 Markdown으로 정리하고 중간 승인 대기 없이 개발을 진행한다.

## 목적

처음 접속한 사람이 시연을 시작하고 같은 사건의 감지·라이더 확인·대응·주문 인계·보고서를 이해하게 한다. 새로고침과 통신 지연에서도 서버에 수신된 사건과 화면의 관계를 명확히 한다.

## 요구사항과 완료 기준

1. 조작 통합: 통합 시연의 기본 조작은 시나리오, 자동/수동 모드, 시작/일시정지/이어서 재생, 다시 시작으로 통일한다. 느린 재생·센서 끊기·상세 링크는 접을 수 있는 실험 옵션에 둔다. 시작은 서버 연결을 포함한다.
2. 발표 모드: 넓은 화면에서는 라이더·관제·센서 근거를 한 행에 배치하고 상단 조작은 유지한다. 작은 화면은 세로 배치한다. 전체 라이더·전체 파형·세부 기록은 상세 모드로 확인한다. 1366×768 및 1920×1080을 목표로 하되 글자 크기 확대 시 내용은 잘리지 않고 스크롤된다.
3. 복구: 해당 탭의 sessionStorage에 발표 키와 순서가 고정된 미확인 명령을 저장한다. localStorage와 보고서에는 쓰기 키를 저장하지 않는다. 새로고침 뒤 명시적인 이어가기/새로 시작을 제공한다. 서버 조회 → 저장된 명령의 동일성 검증·재전송 → 서버 일시정지 → 서버 상태로 동기화 순서로 복구한다. 서버가 이미 받은 명령도 동일성 검증 후 정리하여 복제된 탭의 충돌을 숨기지 않는다. 자동 재생하지 않는다. 만료·권한 오류·순번 충돌이면 새 세션이 필요함을 표시한다. 저장소 사용 불가도 시연 자체를 막지 않는다.
4. 보고서 일관성: 연결된 시연의 모든 보고서 진입은 동일한 서버 세션을 가리킨다. 별도 창에는 읽기 링크만 전달한다. 연결하지 않은 재생 보고서는 로컬 자료임을 명시한다. 서버 수신 시각·출처·품질 제한·대응 종료의 의미가 보인다.
5. 상황 설명: 후보·응답 대기·미응답 대응·주문 인계·라이더 취소·정상·판정 불가·시연 종료를 자연어로 설명한다. 서버 수신 성공과 판정 결과, 구조 완료를 혼동하지 않는다. 현재 단계는 색상과 문구로 표시한다.
6. 진입/자료 가져오기: 로그인 없는 시연 진입을 주요 행동으로 제공한다. 모니터는 의미 있는 실험 그룹, 내려받을 수 있는 유효한 replay 예제 JSON, 생성 전 미리보기, 필드별 검증 오류를 제공한다. 기존 서버 검증을 유지하고 원본 없는 파형을 만들지 않는다.
7. 라이더 홈: 헬멧/휴대폰 센서 출처, 센서·위치 최신성, 연결/권한 문제에 맞는 다음 행동을 보여준다. 웹의 화면 잠금·백그라운드 한계를 드러낸다. 웹 경고음은 사용자 동작으로 준비/시험할 수 있고, 브라우저 차단 시 안내하며 대응 종료 시 중단한다. 실제 기기별 백그라운드 검증은 수행 결과를 별도로 남긴다.

복구 중에는 라이더 응답·관제 조작을 잠가 서버에 남지 않는 로컬 조작을 방지한다. 서로 다른 발표 세션의 창은 상태·명령을 섞지 않는다. 같은 발표에서 연 라이더/관제 창만 해당 발표와 동기화한다.

## 제약

- Expo 57 / React Native 0.86 / Node 24, 기존 의존성을 사용한다.
- 센서 판정 규칙·운영 사고 처리·외부 발송 정책은 변경하지 않는다.
- 발표는 격리된 시연이다. 실제 문자·119·배차를 발송하지 않는다.
- 기존 스테이징 파일 `apps/server/scripts/update-rule-tests.py`, `apps/server/test-results.tmp`는 변경하거나 커밋하지 않는다.
- 배포/완료는 테스트·타입·린트·빌드 및 공개 URL 확인의 실제 결과로 기록한다.
- 브라우저 연결이 없으면 시각 검증을 수행했다고 주장하지 않는다.

## 검증 범위

동일 명령의 응답 유실 후 새로고침, 만료/잘못된 저장 내용, 별도 탭 보고서, 데이터 부족/정상 분기, 잘못된 JSON 필드, 브라우저 오디오 차단/종료를 테스트한다. 배포 후 발표 전용 세션에서 후보→종결 및 정상/부족 자료를 확인한다.

# 발표 시연 실행 안내

통합 화면의 재생·라이더 응답·관제 조작을 서버가 수신하고, 발표 모니터에서 같은 사건의 근거와 진행 기록을 확인합니다. 발표 세션은 운영 사고 저장소 및 실제 문자·119·배차와 분리됩니다.

## 한 번에 실행

Node 24와 각 앱의 기존 의존성이 설치된 PC에서 실행합니다.

```powershell
cd rider-guard/apps/server
npm.cmd run presentation
```

웹 화면을 빌드한 뒤 로컬 서버를 시작합니다. 터미널에 두 주소가 출력되면 접속하세요. 종료는 Ctrl+C입니다.

- 통합 시연: http://localhost:4001/demo
- 발표 운영 모니터: http://localhost:4001/ops/presentation

이 미리보기는 같은 PC에서만 접속합니다. DB는 `apps/server/data/presentation-preview.db`이며, 기존 서버 환경변수나 클라우드 DB를 사용하지 않습니다.

## 발표 순서

1. 통합 시연에서 **정상 주행 → A1 충돌**을 고르고 **전체 흐름 자동 시연**을 누릅니다. 서버 세션을 연결한 뒤 처음부터 시작합니다.
2. **수신 중인 운영 모니터**를 새 창으로 엽니다. 운영 토큰 없이 해당 발표 세션만 읽을 수 있습니다. 원본 시연 창은 열어 둡니다.
3. 정상 주행 → 실측 충격 파형 → 사고 후보 → 라이더 확인 대기 → 연락·119 처리 시연 → 주문 보류·대체 배차 → 대응 종료를 설명합니다. 약 1분 뒤 자동으로 멈춥니다. **응답 대기 건너뛰기**로 발표 시간을 줄일 수 있습니다.
4. 자동 진행 중에도 **괜찮아요**, **도움이 필요해요**로 분기를 보여줄 수 있습니다. 센서를 끊고 사건 구간을 지나면 판정 누락으로 남습니다.
5. 모니터에서 판정 근거·수신 시각·주문 인계·타임라인을 확인하고 **JSON 저장** 또는 **보고서 인쇄**를 사용합니다. PDF 저장은 인쇄 대화상자에서 선택할 수 있습니다.

**전체 흐름 다시 시연** 또는 시나리오 선택으로 재시작합니다. 통신이 끊기면 통합 화면의 시계를 멈추고 미확인 명령을 보존합니다. 수신 회복을 확인한 뒤 **이어서 재생**을 누릅니다.

## 비교할 사례

| 사례 | 보여주는 기능 |
| --- | --- |
| A1 충돌 | 후보 감지부터 대응·주문 인계·보고서까지 |
| D7 요철 노면 | 후보 없는 정상 신호 수신과 배달 유지 |
| D6 연석 | 정상으로 분류된 실험도 현재 판정창이 부족하면 판정 제한 표시 |
| B3 정지 중 피추돌 | 정지 상태의 사고 후보 감지 |
| C3 충격 구간 누락 | 후보 근거와 데이터 품질 제한을 함께 확인 |

센서 수신 누락과 불충분한 데이터는 정상 판정이 아닙니다. 출처·후보 여부·품질을 구분해서 설명하세요.

## 실험·시뮬레이션 자료 수신

발표 모니터 첫 화면에서 **ESP32·MPU6050 실측 29조건**을 직접 선택할 수 있습니다. 해당 원본 파형을 운영과 같은 분석 코드로 재분석합니다.

외부 시뮬레이션·실험 판정은 **detection.v1 JSON** 파일 또는 붙여넣기로 받습니다. 기존 `/v1/detections` 계약과 같은 형식이며 `source.mode: "replay"`인 자료만 가져옵니다. 파일은 60KB 이하입니다. 원시 CSV·NPZ는 직접 받지 않으며, 기존 지표 라우터로 판정 JSON으로 변환한 뒤 입력합니다.

필수 항목은 `schema_version`, `detection_id`, `rider_id`, `occurred_at`, 재생 출처를 포함한 `source`, `detector`, `result`, `evidence`입니다. [지표 라우터 연동 계약](../README.md#지표-라우터-연동-post-v1detections)을 참고하세요.

외부 JSON은 제공된 후보·근거를 그대로 표시합니다. 원본 파형이 없으면 파형을 만들지 않고, 실행 전체 최대값과 후보 관찰창 값을 구분합니다. 발표 라이더·주문은 예시이며 실제 계정을 변경하지 않습니다.

## 연결과 배포

기존 `/ops` 상단의 발표 모니터 링크로도 시작할 수 있습니다. 발표 세션은 별도 읽기 키로 조회하며 기존 운영 조회는 계속 `OPS_TOKEN`으로 보호됩니다. 보고서 JSON에는 접근 키를 포함하지 않습니다.

배포 환경에서는 프런트와 서버 변경을 모두 배포하고 `EXPO_PUBLIC_API_URL`이 변경한 서버를 가리키도록 해야 합니다. `/demo-api/presentations`는 실제 발송을 수행하지 않으므로 운영 서버의 `DEMO_MODE=true` 설정은 필요하지 않습니다. 이 작업은 배포를 수행하지 않았습니다.

배포 서버의 읽기 링크는 다른 기기에서도 볼 수 있습니다. 라이더·관제 조작 동기화는 같은 브라우저의 창끼리 동작합니다. 원본 시연 탭이 닫히면 모니터는 수신 지연을 표시합니다. 발표 세션은 24시간 뒤 만료됩니다.

# Webapp UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans for task verification. Independent file ownership is dispatched under superpowers:dispatching-parallel-agents; root integrates interfaces and performs final review.

**Goal:** 시작·진행·복구·결과가 일관된 발표용 웹앱과 명확한 라이더 보호 상태를 제공한다.

**Architecture:** 기존 API/순수 시연 엔진을 유지한다. 전송 복구는 클라이언트 브리지에, 발표 조작은 단일 패널에, 외부 자료 미리보기는 모니터에 둔다. 센서·위치·오디오 안내는 라이더 기능에 한정한다.

**Tech Stack:** Expo 57, React Native 0.86, TypeScript, Node 24, Hono, libSQL, node:test.

**Spec:** `../specs/2026-10-01-webapp-ux.md`

## Global Constraints

- Expo 57 / React Native 0.86 / Node 24, 기존 의존성을 사용한다.
- 센서 판정 규칙·운영 사고 처리·외부 발송 정책은 변경하지 않는다.
- 발표는 격리된 시연이다. 실제 문자·119·배차를 발송하지 않는다.
- 기존 스테이징 파일은 변경하거나 커밋하지 않는다.
- 키는 탭 sessionStorage에 한정하며 localStorage/보고서/쓰기 링크 공유에 넣지 않는다.

## Review Focus

- 응답이 유실된 명령을 복구할 때 순번·사건 시각이 중복 적용되지 않는가.
- 새로 열린 보고서 창이 다른 로컬 사건을 보여주지 않는가.
- 정상·판정 불가·라이더 취소가 완료/사고 확정으로 오인되지 않는가.
- 업로드/붙여넣기 수정 후 이전 미리보기로 세션이 생성되지 않는가.
- 오디오가 차단되거나 화면을 떠나도 보호 준비/경고 재생 상태를 과장하지 않는가.

## Workflow

1. 명세·계획 작성 및 기존 테스트 확인.
2. 복구/보고서 데이터, 발표 UI, 모니터 가져오기 작업을 파일 소유권으로 나눠 진행.
3. 루트는 로그인 진입·라이더 홈·웹 경고음 구현.
4. 인터페이스 통합, 회귀 테스트, 타입/린트, 웹 빌드.
5. 별도 검토 및 수정, 실행 안내 업데이트, 기존 배포 흐름으로 반영 후 공개 검증.

- Task 3: 관련 테스트 17개 및 서버 전체 145개 통과. 서버 타입 검사·린트 통과.

- 복구 검증 보강: GET의 마지막 순번만으로 저장된 명령을 지우면 복제 탭의 다른 명령을 숨길 수 있어, 기존 멱등 POST로 동일성을 확인한 뒤 배치별 정리한다. API 변경 없이 충돌을 드러낸다.
- 통합 1차 검증: 라이더 58개, 타입 검사·린트, 웹 export 통과. 웹 export에는 기존 Android 전용 `google-services.json` 부재 안내가 남지만 exit 0으로 정적 산출물이 생성됨.
- 독립 리뷰: 복구 snapshot의 다른 세션 혼입(P1), 휴대폰 센서 지연 시 헬멧 연결 안내(P2), 복구 전 응답 유실(P2)을 발견해 회귀 사례와 함께 수정한다. 웹 경고음은 화면 focus 해제 시 중단하도록 보강한다.
- 리뷰 수정: 서버 세션별 상태·명령·읽기 링크를 분리했고, 라이더·관제·단독 재생 버튼의 복구 전 조작을 차단했다. 서로 다른 복구 세션 12초/3초에서 이어가기 후 화면과 서버가 각각 12.5초/3.5초로 일치하는 회귀 검증을 추가했다.

- 최종 기능 검증: 라이더 69/69(발표 전송·복구 33개 포함), 서버 145/145 통과. 양쪽 타입 검사·린트 통과. 독립 재검토에서 중요 잔여 결함 없음, 최종 검토 대상 테스트 41/41 통과.

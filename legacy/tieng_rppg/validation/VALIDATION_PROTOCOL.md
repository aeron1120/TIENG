# TIENG TouchFree Vitals — 정량 검증 프로토콜 (기획서 6.3 산출물)

> 목적: 카메라 rPPG HR 추정값을 **펄스옥시미터(CMS50E) 기준값**과 비교해 정량 오차를 산출하고,
> **SQI 게이팅의 효과(정확도↑ 대신 커버리지↓)**를 데이터로 증명한다.
> 이 프로토콜은 발표장에서 그대로 근거로 인용할 수 있게 설계됨. 코드는 `evaluate.py`(기존)로 산출.

---

## 0. 핵심 검증 가설 (발표 스토리)

| # | 가설 | 근거가 될 산출물 |
|---|------|------------------|
| H1 | 정적·조명고정 조건에서 카메라 단독 HR은 임상 허용범위에 근접한다 | static 시나리오 MAE/±5bpm |
| H2 | **SQI 게이팅을 켜면 나쁜 구간이 제거되어 오차가 크게 준다** (제품 핵심) | 전체 vs 게이팅 MAE 비교 (특히 head_motion) |
| H3 | 그 대가는 **커버리지 감소**이며, 우리는 이를 숨기지 않고 함께 보고한다 | 게이팅 후 표시율(display rate) |

> **정직성 원칙**: 정확도 지표는 **항상 커버리지와 한 쌍으로** 보고한다. 게이팅 후 MAE만 자랑하고 표시율을 숨기면 안 됨. 이게 제품 철학("모를 땐 보류")과 검증이 일치하는 지점.

## 1. 평가 지표 정의

기준값 `ref`(펄스옥시미터 PR), 추정값 `pred`(카메라 heart_bpm). 시간 정렬 후 N개의 쌍 `(pred_i, ref_i)`에 대해:

```
error_i = pred_i - ref_i

ME  (bias)  = mean(error_i)                     # 양수=과대추정, 계통오차 방향
MAE         = mean(|error_i|)                    # 주 지표 (논문 대조)
RMSE        = sqrt(mean(error_i^2))              # 큰 오차에 민감
r  (Pearson)= corr(pred, ref)                    # 추세 일치도
Acc±5       = (|error_i| <= 5 인 비율) * 100 [%]  # 임상 관용 지표
Acc±10      = (|error_i| <= 10 인 비율) * 100 [%]
```

**Bland-Altman(일치도, 필수)**:
```
bias  = ME
LoA   = bias ± 1.96 * SD(error_i)                # 95% 일치 한계
```
> 상관계수 r만 보고하면 안 됨 — r이 높아도 계통 오프셋(bias)이 클 수 있음. **Bland-Altman이 의료성 주장에서 표준.**

**커버리지 지표(게이팅 스토리의 반쪽)**:
```
display_rate = (표시된 프레임 수 / 전체 프레임 수) * 100 [%]
n_pairs      = 실제 비교에 쓰인 쌍의 개수  # 표에 반드시 병기
```

> 각 셀(시나리오×조건)마다 `n_pairs`를 반드시 표기. 작은 n에서 나온 좋은 MAE는 신뢰 못 함.

## 2. 실험 시나리오 (run_experiment.py 3종)

모든 시나리오 공통 기본 조건: 웹캠에서 **약 50cm**, 얼굴 정면, ROI(이마+양볼) 가시, 시나리오당 **60초**(`--duration`으로 조절). 조용한 실내.

| 시나리오 | 피험자 동작 | 조명 | 이 시나리오로 증명하려는 것 |
|----------|-------------|------|------------------------------|
| **static** | 정지·정면 응시, 말 안 함 | 고정(예 300~500 lux) | H1: 최상 조건 기준선 정확도 |
| **lighting** | 정지 | **중간에 변화**(스탠드 on/off 또는 창측 이동) | q_brightness·저조도 강건성, 조명 변화 시 SQI 반응 |
| **head_motion** | 통제된 머리 움직임(천천히 좌우 회전·끄덕임 반복) | 고정 | **H2 핵심**: motion으로 SQI 하락 → 게이팅이 나쁜 구간 제거 |

> head_motion은 "제품이 무너지는 걸 보여주는" 시나리오가 아니라 **"제품이 정직하게 보류하는 걸 보여주는"** 시나리오다. 발표에서 이 프레이밍이 중요.

각 시나리오는 **동시에 펄스옥시미터를 착용**하고 녹화한다(§3 동기화).

## 3. 시간 동기화 (가장 실수 나기 쉬운 부분)

두 로그의 시간축이 다르다:
- **카메라 CSV**: `elapsed_sec` = 프로세스 시작 기준 경과초, HR은 수 Hz로 갱신.
- **CMS50E**: 기기/소프트웨어에 따라 다름. 아래 데이터 취득 경로를 먼저 확정할 것.

### 3-1. 기준값(ref) 취득 경로 — 셋 중 하나 확정 필요
1. **USB + 벤더 SW**(CMS50E/CMS50D+ 계열 "SpO2 Assistant" 등): 세션을 CSV로 export, PR이 초당 1개 내외. → **권장**, 연속 기준값.
2. **Bluetooth 앱**(CMS50E-BT 등): 앱에서 export. 취급 동일.
3. **기기 화면만**(export 불가 모델): 5~10초 간격 수기 기록. 연속성 낮음 → static 정도만 가능, head_motion엔 원칙적으로 부적합.

> 구매 전 체크: **PC/앱으로 PR을 CSV로 뽑을 수 있는 모델인지 반드시 확인.** export 안 되면 이 프로토콜의 절반(연속 비교)이 불가능.

> **MD300C22(경로 3) 사용 시 head_motion 예외**: 손가락 PR 값 자체는 머리 움직임과 무관해 안정적이므로, 판독 간격을 **1초**로 좁히면(대신 static/lighting은 2초 유지) 연속성 우려를 완화하고 head_motion에도 쓸 수 있다. 자세한 절차는 `MEASUREMENT_SESSION_GUIDE.md` 참고.

### 3-2. 정렬 절차 (권장: 러프 정렬 → 상호상관 미세보정)
1. **공통 t=0 만들기**: 녹화 시작 시 카메라 앞에서 **손으로 명확한 신호 이벤트**(예: 3초간 크게 심호흡 or 손 흔들기)를 준다. 두 로그에서 이 이벤트로 대략적 오프셋 파악.
2. **공통 1Hz 격자로 리샘플**: 두 HR 시계열을 1초 격자에 선형보간.
3. **상호상관으로 미세 오프셋**: 지연 `τ ∈ [-5s, +5s]` 범위에서 두 시계열 상관을 최대화하는 `τ*`를 찾아 정렬. **구현됨** — `evaluate.py --auto-offset`(`lag_search()`). 상관계수는 bias에 영향받지 않으므로 MAE를 직접 최소화하는 수동 offset 탐색보다 원칙적임.
4. **정렬 후 쌍 생성**: 같은 시각의 `(pred, ref)`만 비교. 게이팅 조건은 그 시각의 `heart_sqi`로 판정.

> 주의: 펄스옥시미터 PR도 지연·평활이 있음(내부 평균화). 절대 프레임 단위 정합을 기대하지 말고 **1초 격자 + 상관 정렬**로 충분.

## 4. 분석 설계 — 전체 vs SQI 게이팅 (제품 핵심 증명)

각 시나리오에서 **동일한 데이터로 지표를 두 번** 계산한다:

| 조건 | 포함 프레임 | 의미 |
|------|-------------|------|
| **all** | HR이 산출된 모든 프레임 | 게이팅 없을 때의 순수 성능 |
| **gated** | `heart_sqi >= 0.50` 인 프레임만 | 제품이 실제로 사용자에게 보여주는 값 |

산출 표(시나리오 × {all, gated}):

```
scenario   cond    n_pairs  ME    MAE   RMSE  r     Acc±5  Acc±10  display_rate
static     all     ...
static     gated   ...
lighting   all     ...
lighting   gated   ...
head_motion all    ...
head_motion gated  ...
```

**기대 패턴(논문과 정합)**:
- static: all ≈ gated (원래 좋음). MAE ~5bpm 근처.
- head_motion: **all은 MAE 큼(논문 13.4 수준) → gated에서 급감(논문 2.89 방향)**, 단 `display_rate`는 크게 떨어짐. 이 한 줄이 H2+H3를 동시에 증명.

> **`--sqi-hysteresis`는 표시 전용이므로 분석에 쓰지 말 것.** 게이팅 판정은 CSV의 raw `heart_sqi`/`heart_status` 컬럼으로만. (HANDOFF §5와 일치)

## 5. 피험자 & 표본 계획

예선 데모 기준 현실적 규모:

| 항목 | 최소(예선) | 권장 |
|------|-----------|------|
| 피험자 수 | 1(본인) | 3~5명 |
| 피부톤 다양성 | — | Fitzpatrick 다양하게(rPPG는 피부톤 민감) |
| 시나리오당 반복 | 1회 | 3회 |
| 1인 총 녹화 | 3분(3×60s) | 9분(3×3×60s) |

보고: **피험자별 표 + 전체 pooled 표.** N이 작아도 정직하게 "N=1~3, 예비 검증"이라 명시하면 신뢰가 오히려 올라감. 과대 일반화가 감점 요인.

> HANDOFF §5: "논문 성능치는 단일 피험자 기준. ±3bpm는 레이더 융합값이고 카메라 단독 정적은 MAE 4.66." → **우리 표에서도 카메라 단독임을 못박고, 레이더 수치를 우리 성능처럼 인용하지 말 것.**

## 6. 합격 기준 (논문 목표치 대비)

| 조건 | 목표 | 근거(논문) |
|------|------|-----------|
| static, gated | MAE ≤ 5bpm, Acc±5 ≥ 80% | MAE 4.66 / ±5bpm 81.1% |
| head_motion | gated MAE가 all MAE 대비 **유의미하게 감소**(방향 재현) | 13.4 → 2.89 |
| 전 조건 | Bland-Altman bias가 0 근처, LoA 보고 | 표준 일치도 |

> 목표 미달이어도 실패 아님 — "정적 조건에서만 유효"라는 한계를 데이터로 확인하는 것 자체가 정직한 포지셔닝의 근거(HANDOFF §1 제품 철학).

## 7. evaluate.py 인터페이스 (폴더 연결 후 확정/보완)

기존 `evaluate.py`가 있음(HANDOFF: "펄스옥시미터 CSV 대비 MAE/RMSE 등"). 이 프로토콜에 맞추려면 아래를 확인/보완:

```powershell
# 실제 CLI (확정됨, MEASUREMENT_SESSION_GUIDE.md와 일치)
python evaluate.py --demo run.csv --ref oximeter.csv --sqi-gate 0.50 --auto-offset --out report/
```

폴더 연결되면 확인할 것:
1. `--ref` CSV의 컬럼/타임스탬프 포맷 파싱 (§3-1 취득 경로에 맞게)
2. **1Hz 리샘플 + lag-search 정렬**(§3-2) — **구현됨**(`--auto-offset`)
3. **all vs gated 두 조건 동시 출력**(§4) 여부 → 없으면 추가
4. **Bland-Altman(bias/LoA) + n_pairs + display_rate** 출력 여부 — **LoA는 summary.csv의 `loa_lower_bpm`/`loa_upper_bpm` 컬럼으로 출력됨**(PNG 외 수치 확인 가능), n_pairs=`n` 컬럼, display_rate=콘솔의 `SQI>=gate coverage`
5. `--sqi-hysteresis`가 아니라 **raw `heart_sqi`**로 게이팅하는지 확인

카메라 CSV 컬럼(HANDOFF §7, 변경 없음): `elapsed_sec, heart_bpm, heart_sqi, heart_status, ...`

## 8. 실행 순서 요약

1. 펄스옥시미터 확보(**export 가능 모델 확인** — §3-1).
2. `run_experiment.py`로 3시나리오 녹화 + 동시에 옥시미터 녹화(§2, §3 동기화 이벤트 포함).
3. `evaluate.py`로 정렬·지표 산출(§4 all/gated 표).
4. 표를 기획서 6.3 + 발표 슬라이드에 삽입, H1~H3 스토리로 서술.

> 옥시미터가 아직 없어도 `run_experiment.py` 요약표(표시율/SQI평균/FPS)만으로 **시나리오 간 비교 스토리**는 지금 가능(HANDOFF §6-A). 절대 오차(MAE)는 옥시미터 확보 후.

## 부록. 발표 예상 질문 대비

- **"카메라로 심박을 어떻게 믿냐?"** → 안 믿을 땐 안 보여준다(SQI 게이팅). head_motion 표의 게이팅 전후 MAE로 증명.
- **"표시율이 낮으면 쓸모없지 않나?"** → 순간값이 아니라 **트렌드·장시간 무동작 신호**가 돌봄 가치(HANDOFF §1-3, §6-B). 커버리지 한계는 인정하고 트렌드로 보완.
- **"의료기기냐?"** → 아님. 웰니스 데모. SpO2/혈압 미구현·미주장.
- **"피험자 몇 명이냐?"** → N 정직하게 밝히고 "예비 검증" 명시.

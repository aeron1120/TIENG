# 발표 시연 실행 안내

통합 화면의 재생·라이더 응답·관제 조작을 서버가 수신하고, 발표 모니터에서 같은 사건의 근거와 진행 기록을 확인합니다. 발표 세션은 운영 사고 저장소 및 실제 문자·119·배차와 분리됩니다.

## 배포된 시연 화면

- 통합 시연: https://tieng.pages.dev/demo
- 발표 운영 모니터: https://rider-guard-api-ejwy.onrender.com/ops/presentation

발표는 위 배포 주소에서 진행합니다. 설치나 로컬 서버 실행은 필요 없습니다. 통합 시연에서 **자동 → 시작**을 누르면 서버 연결부터 재생까지 진행하며, **보고서**는 같은 서버 사건을 보여줍니다.

기본 발표 보기는 상태·카운트다운·처리 결과 중심으로 표시합니다. 긴 설명, 판정 규칙, 출처, 주문별 안내 이력은 **상세 보기**에서 확인합니다. 판정 불가·데이터 품질 제한과 연결 오류는 기본 보기에서도 유지합니다.

## 발표 순서

1. 첫 화면의 **로그인 없이 시연 시작** 또는 `/demo`에서 **A1 충돌 → 자동 → 시작**을 누릅니다. 서버 세션을 연결한 뒤 재생합니다. 수동 모드는 라이더·관제 버튼을 직접 조작합니다.
2. 기본 **발표 보기**에서 라이더·관제·센서 근거를 함께 설명합니다. **보고서**를 새 창으로 열면 운영 토큰 없이 같은 발표 세션의 서버 기록을 볼 수 있습니다. 원본 시연 창은 열어 둡니다. 전체 라이더·파형은 **상세 보기**, 느린 재생·센서 끊기·단독 창은 **옵션**에서 확인합니다.
3. 정상 주행 → 실측 충격 파형 → 사고 후보 → 라이더 확인 대기 → 연락·119 처리 시연 → 주문 보류·대체 배차 → 대응 종료를 설명합니다. 약 1분 뒤 자동으로 멈춥니다. **대기 건너뛰기**로 발표 시간을 줄일 수 있습니다.
4. 자동 진행 중에도 **괜찮아요**, **도움이 필요해요**로 분기를 보여줄 수 있습니다. 센서를 끊고 사건 구간을 지나면 판정 누락으로 남습니다.
5. 모니터에서 판정 근거·수신 시각·주문 인계·타임라인을 확인하고 **JSON 저장** 또는 **보고서 인쇄**를 사용합니다. PDF 저장은 인쇄 대화상자에서 선택할 수 있습니다.

**다시 시작**으로 재시작하거나 시나리오를 선택한 뒤 **시작**을 누릅니다. 통신이 끊기면 통합 화면의 시계를 멈추고 미확인 명령을 보존합니다. 수신 회복을 확인한 뒤 **이어서 재생**을 누릅니다.

## 새로고침과 보고서

같은 탭을 새로고침하면 **이전 시연 이어가기 / 새로 시작**을 선택할 수 있습니다. 이어가기는 서버가 받은 순번과 저장된 명령의 동일성을 확인하고 같은 명령을 재전송한 뒤 일시정지 상태로 복구합니다. 복구 전에는 라이더·관제 조작을 잠급니다. 복구 후 **이어서 재생**을 눌러야 시계가 움직입니다.

복구 정보와 쓰기 키는 해당 탭의 `sessionStorage`에만 저장됩니다. 브라우저 저장을 사용할 수 없으면 경고를 표시하고 현재 탭에서 시연합니다. 이 경우 새로고침 복구는 보장하지 않습니다. 탭을 닫았거나 세션이 만료된 경우 새 시연을 시작하세요.

연결된 시연의 보고서 진입은 서버가 수신한 같은 사건을 기준으로 합니다. 별도 창에 전달하는 링크는 읽기 전용입니다. 연결 없이 생성된 기존 로컬 보고서는 서버 수신 자료가 아님을 표시합니다. 수신 완료는 정상 판정이나 실제 구조 완료를 의미하지 않습니다.

## 비교할 사례

| 사례 | 보여주는 기능 |
| --- | --- |
| A1 충돌 | 후보 감지부터 대응·주문 인계·보고서까지 |
| D7 요철 노면 | 후보 없는 정상 신호 수신과 배달 유지 |
| D6 연석 | 정상으로 분류된 실험도 현재 판정창이 부족하면 판정 제한 표시 |
| B3 정지 중 피추돌 | 정지 상태의 사고 후보 감지 |
| C3 충격 구간 누락 | 후보 근거와 데이터 품질 제한을 함께 확인 |

센서 수신 누락과 불충분한 데이터는 정상 판정이 아닙니다. 출처·후보 여부·품질을 구분해서 설명하세요.

## 실험·시뮬레이션 자료 수신

발표 모니터 첫 화면에서 **ESP32·MPU6050 실측 29조건**을 직접 선택할 수 있습니다. 해당 원본 파형을 운영과 같은 분석 코드로 재분석합니다.

외부 시뮬레이션·실험 판정은 **detection.v1 JSON** 파일 또는 붙여넣기로 받습니다. 예제 JSON을 내려받아 형식을 확인하고, 붙여넣기/파일 선택 후 미리보기에서 출처·후보·근거를 확인한 다음 시연을 시작합니다. 입력을 수정하면 다시 검증해야 합니다. 기존 `/v1/detections` 계약과 같은 형식이며 `source.mode: "replay"`인 자료만 가져옵니다. 파일은 60KB 이하입니다. 원시 CSV·NPZ는 직접 받지 않으며, 기존 지표 라우터로 판정 JSON으로 변환한 뒤 입력합니다.

필수 항목은 `schema_version`, `detection_id`, `rider_id`, `occurred_at`, 재생 출처를 포함한 `source`, `detector`, `result`, `evidence`입니다. [지표 라우터 연동 계약](../README.md#지표-라우터-연동-post-v1detections)을 참고하세요.

외부 JSON은 제공된 후보·근거를 그대로 표시합니다. 원본 파형이 없으면 파형을 만들지 않고, 실행 전체 최대값과 후보 관찰창 값을 구분합니다. 발표 라이더·주문은 예시이며 실제 계정을 변경하지 않습니다.

## 연결과 배포

기존 `/ops` 상단의 발표 모니터 링크로도 시작할 수 있습니다. 발표 세션은 별도 읽기 키로 조회하며 기존 운영 조회는 계속 `OPS_TOKEN`으로 보호됩니다. 보고서 JSON에는 접근 키를 포함하지 않습니다.

배포 환경에서는 프런트와 서버 변경을 모두 배포하고 `EXPO_PUBLIC_API_URL`이 변경한 서버를 가리키도록 해야 합니다. `/demo-api/presentations`는 실제 발송을 수행하지 않으므로 운영 서버의 `DEMO_MODE=true` 설정은 필요하지 않습니다. 위 공개 주소에는 발표 기능이 배포되어 있습니다.

배포 서버의 읽기 링크는 다른 기기에서도 볼 수 있습니다. 라이더·관제 조작 동기화는 같은 브라우저에서 같은 발표에 연결한 창끼리 동작합니다. 단독 창은 원본 시연의 **옵션**에서 열고, 원본 탭을 유지하세요. 서로 다른 발표 세션은 상태를 섞지 않습니다. 원본 화면을 떠나면 재생을 일시정지하고 단독 창 조작을 잠급니다. 갑작스러운 창 종료는 연결 확인 시간이 지난 뒤 감지합니다. 모니터에는 수신 지연이 표시되며, 서버 읽기 링크로 마지막 기록을 볼 수 있습니다. 발표 세션은 24시간 뒤 만료됩니다.

## 라이더 웹 화면

로그인 후 홈에서는 감지 센서 출처, 마지막 측정 시각, 서버에 전달된 위치 시각과 필요한 행동을 확인합니다. 화면용 현재 GPS와 서버에 전달된 위치는 서로 다를 수 있습니다. 오래된 센서 측정은 이전 서버 응답이 fresh여도 보호 중으로 표시하지 않습니다.

**경고음 준비·시험**을 직접 눌러 브라우저 소리를 준비할 수 있습니다. 사고 확인 대기 중에는 준비한 경고음을 반복하며, 응답·대기 종료·화면 이탈 때 중단합니다. **소리 끄기**와 브라우저 차단 안내를 제공합니다. 기기 음량·화면 잠금·백그라운드 제약은 남아 있으며 네이티브 경고음 지원을 의미하지 않습니다.

실제 iOS/Android의 소리·잠금·권한 동작과 발표 화면의 투사 가독성은 해당 기기에서 별도 리허설해야 합니다. 이번 작업 환경에는 연결된 브라우저가 없어 스크린샷 기반 시각 검증을 하지 못했습니다.

## 개발용 선택사항: 로컬 미리보기

배포 전 개발 확인이 필요할 때만 사용합니다. Node 24와 각 앱의 의존성이 설치된 PC에서 실행하세요.

```powershell
cd rider-guard/apps/server
npm.cmd run presentation
```

웹 화면을 빌드한 뒤 로컬 서버를 시작합니다. 통합 시연은 `http://localhost:4001/demo`, 발표 모니터는 `http://localhost:4001/ops/presentation`입니다. 종료는 Ctrl+C입니다. DB는 `apps/server/data/presentation-preview.db`이며 기존 서버 환경변수나 클라우드 DB를 사용하지 않습니다.

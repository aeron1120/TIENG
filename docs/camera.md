# 카메라

심박(rPPG)은 카메라에서 나온다. 그 카메라가 어디 붙어 있는지가 두 갈래다.

```
서버 카메라                          브라우저 카메라
[파이의 CSI / USB 웹캠]              [노트북 웹캠 / 폰 앞카메라]
   └─ 서버가 직접 연다                  └─ 화면을 연 사람의 기기
   core/adapters/rppg.py               web/src/hooks/useDeviceCamera.ts
```

실시간 화면의 카메라 패널에서 **`이 기기` / `서버`** 로 고른다. 서버에 카메라가
없으면 그 칸은 `서버 (없음)` 으로 비활성이다 — 눌리지 않는 이유를 적어 두지 않으면
고장으로 보인다.

## 왜 두 갈래인가

화면이 두 자리에서 열린다. 침실 앞 태블릿은 방에 붙은 카메라를 보면 되지만, 밖에서
주소로 들어온 사람에게는 그 카메라가 없다 — 대신 자기 기기 카메라가 있다.

공개 배포(Render)에는 카메라가 아예 없다. 거기서 값이 나오는 유일한 길이 이쪽이다.

## 무엇이 오가는가

**영상은 브라우저를 벗어나지 않는다.** 프레임에서 안내 박스 안의 피부 픽셀만 골라
평균 RGB 세 숫자로 줄인 뒤 그것만 보낸다.

```
[프레임 640x480]
   ↓  캔버스 160x120 으로 축소, 안내 박스만 잘라냄
[피부 픽셀 판정 (YCrCb)]
   ↓
(t, r, g, b)  ← 초당 30개, 1KB 남짓
   ↓  POST /api/rppg/samples
[서버: core/pulse.py]
```

README §1 이 "영상은 이 기기 밖으로 나가지 않는다"를 비목표로 못박고 있고, 화면에도
그렇게 적혀 있다. 서버가 인터넷 저편에 있어도 그 약속이 그대로 성립해야 해서 이렇게
나눴다. 프레임을 그대로 올리면 생체 영상이 인터넷을 건너간다.

부수적으로 대역폭도 수 Mbps 에서 1KB/s 로 떨어지고, 서버는 영상 디코딩을 하지 않는다
— 무료 플랜의 512MB 로도 여러 사람이 동시에 잰다.

## 계산은 서버가 한다

두 갈래가 **같은 추정기**를 쓴다 (`core/pulse.py` 의 `HrEstimator`). POS → 대역통과 →
Welch → 신뢰도 → 점프 가드 → 표시 EMA 까지 전부 한 벌이다.

브라우저에서 계산하면 그 공식을 두 벌로 유지하게 되고, 두 배포의 숫자가 갈리는 순간
"이 심박은 옥시미터로 검증한 값"이라고 말할 근거가 사라진다
(`legacy/tieng_rppg/validation`, `core/quality.py` 의 이관 기록).

브라우저가 맡는 것은 **픽셀을 봐야만 나오는 값**뿐이다 — 서버에는 프레임이 없어 다시
잴 수 없다.

| 브라우저 | 서버 |
|---|---|
| 피부 픽셀 평균 RGB | 맥파 추출·주파수 분석 |
| 피부 비율 · 밝기 | 신뢰도 판정과 게이트 |
| ROI 흔들림 | 점프 가드 · 표시 EMA |

피부 판정은 파이썬 쪽(`cv2`)과 대조해서 맞췄다. cv2 는 14비트 고정소수점 계수에
DESCALE 반올림을 쓰고 Cr·Cb 에 이미 반올림된 정수 Y 를 뺀다 — 십진수로 실수 계산하면
백만 개 중 수십 개가 갈린다. `useDeviceCamera.ts` 의 `isSkin` 을 내보내는 이유가 그
대조다 (189만 표본에서 판정 일치).

## 값이 남에게 안 보인다

브라우저 카메라로 잰 값은 **그 세션에게만** 간다. 철수가 자기 폰으로 잰 심박이 영희
화면에 뜨면 안 된다 — 로그인 게이트를 앞에 세운 이유가 여기서 실제로 쓰인다.

- 소켓마다 누구인지(세션 토큰)와 무엇을 볼지(소스)를 들고 있다 (`api/ws.py`)
- 열쇠는 세션 토큰이다. `username` 으로 나누면 비회원은 이름이 없어 전부 한 칸에 몰린다
- 소스는 접속 주소로 정한다 (`/ws?source=device`). 붙은 뒤 메시지로 바꾸게 하면
  프론트가 서버 상태를 고르는 셈이 된다 (README §10)

값이 섞여도 화면은 멀쩡해 보인다 — 숫자가 하나 떠 있을 뿐 누구 것인지는 어디에도 안
적혀 있다. 눈으로 확인할 수 없어서 `tests/test_ws.py` 가 대신 잡는다.

## 얼굴 검출을 하지 않는다

브라우저마다 있는 API 가 달라 못 믿는다. 대신 화면 가운데 고정 박스를 보여 주고
사람이 맞추게 한다.

안 맞으면 피부 비율이 떨어져 서버가 값을 보류한다 — **못 맞춘 채로 숫자가 나오지는
않는다.** 미리보기를 좌우 반전하는 이유는 거울이 아니면 맞추려 할수록 반대로 움직이기
때문이고, 브라우저의 '화면 속 화면'을 막아 둔 이유는 그 창에서 반전과 안내 박스를 함께
잃기 때문이다.

## 값이 안 나올 때

| 화면 | 뜻 |
|---|---|
| 진행률이 도는 중 | 창을 채우는 중이다. **첫 값까지 8초** (`MIN_SEC`) |
| `품질 미달` + 진행률 100% | 기다려도 안 나온다. 조명·자세·거리를 고쳐야 한다 |
| `급변 보류` | 신호는 멀쩡한데 값이 튀어 버렸다. 몇 초 뒤 돌아온다 |
| 카드가 비어 있음 | 얼굴이 박스 밖이거나 카메라가 안 열렸다 |

분석 창은 12초고(`WINDOW_SEC`), 신뢰도 게이트는 코드가 아니라
`config/thresholds.yaml` 이 정한다 (README §10).

카메라를 끄면 **3초 뒤** 값이 내려간다 (`api/feeds.py` 의 `STALE_AFTER_S`). 끈 사람의
마지막 심박이 화면에 남아 있으면 멎은 숫자가 실시간인 척하는 것이라, 값을 지어내는
것과 같다 (README §0-4).

## 제약

- **HTTPS 나 localhost 에서만 열린다.** 브라우저가 그 밖에서는 카메라를 안 준다.
  파이의 LAN 화면(`http://<주소>:8000`)에서는 `이 기기` 를 못 쓴다 — 거기서는 서버
  카메라를 쓰면 된다.
- **개입(조명·보호자 알림)은 방을 전제로 한다.** 접속자가 자기 폰으로 재는 값으로
  어느 방 불을 켤지는 정해져 있지 않다. 지금은 지표만 보여 준다.
- **기록에 남지 않는다.** CSV 는 이 방의 기록이고 (`core/csv_logs.py`), 거기에 접속자
  측정을 섞으면 개입 전후 비교가 흐려진다. `/api/logs` 는 회원이면 누구나 받아 갈 수
  있어서 격리와도 어긋난다.
- **기억하지 않는다.** 새로고침하면 서버 센서로 돌아간다. 카메라는 그때그때 켜는
  것이지 기기에 남길 설정이 아니다.

## 서버 카메라 쪽

파이의 CSI 카메라는 libcamera 전용이라 `picamera2`, 개발 PC 의 USB 웹캠은 `opencv` 로
연다. 어느 쪽을 물릴지는 자동 감지하지 않고 `config/device.yaml` 이 정한다 — 시스템
탭에서 바꿀 수도 있다. 배선과 확인 절차는 `docs/hardware.md` 에 있다.

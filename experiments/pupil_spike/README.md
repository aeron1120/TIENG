# 동공 측정 타당성 스파이크

웹캠으로 동공을 **잴 수 있는지** 확인하는 실험. 제품이 아니라 판정용이다.

대광반사(PLR)를 양성 대조로 쓴다. 화면을 어둡게/밝게 번갈아 띄워 동공을 강제로
움직이고 그게 잡히는지 본다. PLR은 동공이 내는 신호 중 **가장 큰 것**이라,
이게 안 보이면 각성·스트레스가 만드는 훨씬 작은 변화는 볼 필요도 없다. 보이면
그 진폭이 잡음의 몇 배인지가 다음 단계의 예산이 된다.

TIENG 본체와 격리돼 있다. `mediapipe` 가 `opencv-contrib-python 5.x` 를 끌고 오는데
본체는 `opencv-python <5` 로 핀이 박혀 있어(4.x 의 CascadeClassifier 가 필요하다)
같은 venv 에 넣으면 rPPG 얼굴 검출이 죽는다. 그래서 여기 전용 venv 를 따로 둔다.

## 실행

```bash
cd experiments/pupil_spike

# 처음 한 번: 전용 venv 와 모델 (모델은 3.6MB 라 저장소에 없다)
python -m venv .venv && .venv/Scripts/python.exe -m pip install mediapipe
curl -sSL -o face_landmarker.task \
  https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/1/face_landmarker.task

.venv/Scripts/python.exe run_plr.py      # 90초. 중단은 q
.venv/Scripts/python.exe analyze.py      # 가장 최근 CSV 판정
```

산출물은 `out/plr_<시각>.csv` 와 같은 이름의 `.png` 곡선.

### 측정 조건 — 지키지 않으면 결과가 무의미하다

- **방 조명은 켜 둘 것.** 화면은 자극일 뿐이고 얼굴 기본 조명은 방이 담당한다.
  방까지 어두우면 어두운 구간에서 눈이 아예 안 보인다 (합성 검증에서 어두울 때
  d' 가 1 아래로 떨어졌다).
- 안경은 벗는다. 렌즈 반사가 홍채를 덮으면 `specular_frac` 이 올라가고 프레임이 버려진다.
- 화면에서 50~70cm, 얼굴은 정면. 90초 동안 머리를 가급적 고정한다 — 앞뒤로 움직이면
  게이트2(홍채 반지름 CV)가 그걸 잡아낸다.
- 눈 `A`/`B` 는 좌/우가 아니라 그냥 두 홍채 그룹의 라벨이다. MediaPipe 의 좌우 명명
  규약이 버전마다 흔들려서 신뢰하지 않았다.

## 게이트

| # | 검사 | 기준 | 떨어지면 |
|---|------|------|----------|
| 1 | 검출 안정성 | 얼굴 ≥95%, 동공 ≥90% | 조명·자세·거리 문제 |
| 2 | 기하 안정성 | 홍채 반지름 CV ≤3% | 검출 잡음이거나 머리가 움직였다 |
| 3 | 동공-홍채 대비 | d' ≥ 1.5 | **가시광 한계.** IR 조명이 답이다 |
| 4 | PLR 분해능 | SNR ≥ 3, 잠복기 ≥100ms | 이 폼팩터로는 동공 신호가 안 나온다 |

**게이트 3이 이 실험의 진짜 관문이다.** 짙은 갈색 홍채는 가시광에서 동공과 밝기가
거의 같다. 여기서 떨어지면 알고리즘을 더 만져도 안 올라가고, 850nm IR 조명 +
IR 통과 필터로 가야 한다는 뜻이다. 실무에서 IR을 쓰는 이유가 정확히 이것이다.

게이트 4의 **잠복기 검사**는 자기 자신을 속이지 않기 위한 것이다. 대광반사는 신경
반사라 200~500ms 잠복기가 있다. 자극과 동시에 값이 변했다면 그건 반사가 아니라
밝기가 바뀌면서 임계값이 밀린 것이다. 진폭과 SNR 이 아무리 좋아도 이 경우 FAIL 이다.

## 이미 확인한 것 (카메라 없이)

합성 눈 영상으로 `pupil.measure` 를 검증했다.

- **비율 복원**: 진짜 0.250~0.600 구간에서 오차 −1.5% ~ −4.7%. 형태학적 열림이
  덩어리를 1px 정도 깎아 생기는 **일정한 음의 편향**이다. PLR 은 변화량을 보므로
  이 편향은 상쇄된다. 절대 mm 값을 주장할 때만 보정하면 된다.
- **분해능**: 동공 반지름 1px 차이가 ratio 0.018 로 분리된다. 단조롭고 선형에 가깝다.
- **d' 의 판별력**: 고대비 22.5 → 갈색눈 수준 2.98 → 구분 불가에서 `None`.
  즉 "타원은 나왔는데 의미 없는" 경우를 숫자로 걸러낸다.
- **밝기 불변성**: 동공 크기를 고정한 채 영상 밝기를 3.6배 바꿔도 측정 ratio 변동이
  **0.0000** 이었다. Otsu 가 같이 따라가기 때문이다. 걱정했던 광학 아티팩트는
  최소한 순수 게인 변화에 대해서는 없다.

분석기도 합성 CSV 3종(정상 / 잡음 과다 / 계단형 아티팩트)으로 PASS·FAIL 판정이
맞는지 확인했다.

## 구성

```
pupil.py     눈 크롭 → 동공 타원 + 대비(d')      ← 안경으로 이식되는 유일한 부분
run_plr.py   웹캠 + FaceMesh + 자극 + CSV        ← 웹캠 단계 전용 발판
analyze.py   CSV → 게이트 판정 + 곡선
```

`run_plr.py` 의 얼굴→눈 크롭은 버릴 코드다. 안경 근접 카메라에는 얼굴이 없어
FaceMesh 가 통째로 못 쓰인다. 그때는 눈이 곧 화면 전체이므로 크롭 단계가 사라지고
`pupil.measure` 에 프레임을 그대로 넣게 된다. 그래서 그 함수는 얼굴이 있었다는
사실조차 모르도록 입력을 "눈 크롭 + 홍채 원"으로 좁혀 뒀다.

안경 단계에서는 홍채 원도 FaceMesh 가 아니라 직접 찾아야 한다 — PuRe 계열이
그 자리에 들어간다.

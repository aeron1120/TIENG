# 발표용 운영 모니터 연결

사용자가 원하는 결과: 통합 시연, 실험 및 시뮬레이션 자료에서 출발해 수신 → 판정 → 라이더 확인 → 대응 → 주문 처리 → 보고서를 한 번에 발표한다. 기존 화면의 실제 측정값과 출처를 유지하고 수신 성공을 확인할 수 있어야 한다.

## 구조

- 기존 순수 시연 엔진을 packages/demo로 공유한다. 앱과 서버가 같은 명령을 같은 순서로 적용한다.
- 서버에 독립된 발표 세션을 저장한다. 운영 사고·실제 문자·신고·배차에는 연결하지 않는다. 공개 시연에서도 사용 가능하며 생성 시 읽기 키와 쓰기 키를 분리한다.
- 통합 시연 연결 버튼은 새 세션을 만들고 처음부터 시작한다. 이후 명령을 순서 번호와 함께 배치 전송한다. 실패한 배치는 보존하고 동일 번호로 재시도한다. 서버는 중복을 재적용하지 않고 순서 누락을 거부한다.
- 운영 모니터 /ops/presentation은 서버 수신 상태를 폴링한다. 통합 시연이 발급한 읽기 링크로 접속하거나 자체 실측·외부 JSON 세션을 시작할 수 있다. 운영 토큰은 발표 세션에 필요하지 않다.
- 내장 ESP32 29조건은 실제 서버 판정과 파형을 사용한다. 외부 detection.v1 JSON은 제공된 근거와 후보를 그대로 표시하며 파형이 없으면 만들어내지 않는다.
- 발표 자동 진행은 기존 본인 확인 대기 후 대응, 시연 연락 및 119, 대체 배차, 보고서까지 진행한다. 정상·센서 누락·본인 괜찮음 분기는 사고 대응으로 강제 진입하지 않는다.

## 화면

발표 모드 표식과 출처, 연결/지연 상태, 수신 시각, 단계 표시, 사건 요약, 측정값·기준 비교, 연락 및 주문, 시간순 기록, 인쇄 가능한 보고서. 모든 동작은 키보드 접근 가능하고 좁은 화면에서 재배치한다. 실패·빈 상태는 다음 행동을 제시한다. 실제 발송을 의미하는 표현은 피하고 시연 처리를 표시한다.

## 검증

서버: 인증 분리, 입력 제한, 세션 격리, 재전송, 순서 충돌, 만료, 서버 재생 판정, JSON 검증, 외부 발송 0건.
앱: 자동 시연 종료, 정상 시나리오, 수신 재시도 및 순서, 기존 수동 동작 회귀.
실행: 양쪽 테스트·타입 검사·린트, 웹 빌드, 브라우저에서 실제 수신과 보고서 및 모바일 배치 확인.
